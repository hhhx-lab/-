# 我的订单页原型图实现说明

对应原型：`前端图片/我的订单.jpg`  
目标路由：`/orders`，并影响 `/orders/:orderNumber` 的详情结构  
当前代码：`apps/web/app/pages/orders/index.vue`、`apps/web/app/pages/orders/[orderNumber].vue`

## 页面定位

“我的订单”应是用户查看小纸条进度、沟通记录、附件、报价和下一步动作的工作台。用户打开页面后，第一眼要知道：

1. 总共有多少订单。
2. 哪些订单正在确认、试跑、待验收、已完成。
3. 当前选中订单的进度和下一步。
4. 可以继续补材料、发消息或联系酷里。

## 顶部导航和标题

导航与其他页面一致，当前页“我的订单”选中，底部有黄绿色指示线。

页面标题：

```text
我的订单
```

副标题：

```text
这里能看到你的小纸条进度、沟通记录和当前状态。
```

右上角有黄绿色便利贴，文案：

```text
有问题就
继续回这个单子里聊
- Kuli :)
```

## 状态统计卡片

标题下方有 5 张统计卡片：

1. 全部订单：12 个，说明“包含历史订单”
2. 需求确认中：2 个，说明“酷里正在确认需求”
3. 试跑初版中：2 个，说明“正在开发和测试中”
4. 待验收：1 个，说明“等你验收和反馈”
5. 已完成：7 个，说明“已交付，期待下次合作”

每张卡片包含图标、标签、数字、单位和说明。状态卡片应可点击过滤左侧订单列表。

当前实现只有状态 tab 和搜索，后续应改为统计卡 + 列表筛选联动。

## 主体布局

主体是左右两栏工作台：

- 左侧：订单列表，约 42% 宽度。
- 右侧：选中订单详情预览，约 58% 宽度。

这意味着 `/orders` 不只是列表页，也应能展示当前选中订单摘要。第一阶段可以在 `/orders` 内实现列表 + 详情预览；点击详情仍可进入 `/orders/:orderNumber`。

## 左侧订单列表

左侧大面板标题为“订单列表”，右上角有下拉筛选“全部状态”。

列表项结构：

- 标题，如“注册 Google 账号并开通 Pro”。
- 订单 ID，如 `KULI-20240518-001`。
- 提交时间。
- 预算，如 `¥30 - ¥80`。
- 状态胶囊，如“需求确认中”。
- 右侧箭头。

选中项：

- 边框变黄绿。
- 背景略亮。
- 右侧状态胶囊保持高亮。

示例订单：

1. 注册 Google 账号并开通 Pro，状态“需求确认中”
2. Claude Code 配置 + 国产模型接入，状态“试跑初版中”
3. PDF 翻译并保留格式，状态“待验收”
4. 课程项目网页 demo，状态“已完成”

列表底部空余区域显示：

```text
没有更多啦，继续写小纸条吧 ✨
```

### 底部动作

- 左侧：补充材料，黑底描边。

按钮应始终在详情面板底部可见。移动端可变成底部 sticky 操作栏。

## 当前实现改造映射

- `apps/web/app/pages/orders/index.vue`
  - 当前为状态 tabs + 搜索 + 简单订单表。需要改为“统计卡片 + 左侧列表 + 右侧详情预览”。
  - 当前 `filteredOrders` 可继续作为左侧列表数据源。
  - 需要新增 `selectedOrderNumber` / `selectedOrder` 状态，默认选择第一条订单。
  - 如果无订单，仍保留当前空状态，但视觉改成原型风格。
- `apps/web/app/pages/orders/[orderNumber].vue`
  - 详情页应复用右侧预览组件，但展开为完整页面。
  - 进度条、沟通记录、附件、报价付款、规则说明应抽成可复用组件。
- `useDisplayText`
  - 继续承担订单状态中文映射，确保不显示英文 status key。

## 数据和组件建议

建议拆分组件：

- `OrderStatusSummaryCards.vue`
- `OrderListPanel.vue`
- `OrderProgressRail.vue`
- `OrderConversationPanel.vue`
- `OrderAttachmentPreview.vue`
- `OrderQuotePaymentCard.vue`

订单列表和详情预览都使用真实 API 数据；如果某些字段缺失，用业务友好的空状态：

- 无附件：显示“还没有补充截图或文件”。
- 无报价：显示“酷里还在确认需求，确认后会给报价范围”。
- 无沟通记录：显示“有问题可以直接在这里问酷里”。

## 响应式要求

- 1200px 以下：主体改为单列，订单列表在上，详情预览在下。
- 760px 以下：统计卡片改为 2 列；进度条改为竖向；附件缩略图横向滚动。
- 480px 以下：状态统计可横向滑动；详情底部动作按钮 sticky；订单列表每项减少预算/时间的同屏密度。

## 组件级实现规格

我的订单页应拆成一个完整工作台，而不是列表页。建议组件：`OrdersPageHeader`、`OrderStatsGrid`、`OrderListPanel`、`OrderListItem`、`OrderDetailPreview`、`OrderProgressRail`、`OriginalDemandCard`、`ConversationCard`、`AttachmentStrip`、`QuotePaymentCard`、`OrderRulesCard`、`OrderActionBar`。

### 1. `OrdersPageHeader`

位置：导航下方，统计卡片上方。

结构：

- 左侧标题“我的订单”。
- 副标题“这里能看到你的小纸条进度、沟通记录和当前状态。”。
- 小星形线稿装饰。
- 右侧黄绿色便利贴。

视觉规格：

- H1 40-48px，字重 850。
- 副标题 15-16px。
- 顶部高度约 108-130px。

便利贴：

- 宽 210-230px，高 140px。
- 文案：“有问题就 / 继续回这个单子里聊 / - Kuli :)”。
- 使用图钉装饰，旋转约 5deg。
- 900px 以下隐藏或移动到标题下方。

### 2. `OrderStatsGrid`

顶部 5 张统计卡片。

布局：

- 桌面端 5 列，间距 14px。
- 每张高 116-126px。
- 760px 以下 2 列；480px 以下横向滑动。

字段：

```ts
type OrderStatCard = {
  label: string;
  count: number;
  unit: "个";
  hint: string;
  statusFilter: string | "all";
  icon: string;
  tone: "neutral" | "orange" | "blue" | "yellow" | "green";
};
```

卡片结构：

- 左侧图标容器 46x46px。
- 右侧/下方标签。
- 大数字，字号 30-34px。
- 单位“个”小号上标感。
- 底部说明。

状态：

- selected：边框黄绿，背景略亮。
- hover：卡片上浮 1px。
- 点击：更新左侧列表过滤，不直接跳路由。

### 3. `OrdersWorkbenchGrid`

主体左右布局。

grid-template-columns: minmax(360px, 0.42fr) minmax(0, 0.58fr);

左栏为 `OrderListPanel`，右栏为 `OrderDetailPreview`。两栏高度建议至少 680px；右侧详情随选中订单变化。

### 5. `OrderListItem`

订单列表项，原型中每项约 104-116px 高。

结构：

- 第一行：
  - 标题，18px，单行省略。
  - 状态胶囊，右侧。
  - 右箭头。
- 第二行：
  - 订单 ID。
- 第三行：
  - 提交时间。
  - 预算范围，右侧。

字段：

```ts
type OrderListItemView = {
  orderNumber: string;
  title: string;
  submittedAt: string;
  budgetRange?: string;
  status: string;
  statusLabel: string;
  statusTone: string;
};
```

样式状态：

- default：灰边框或无边框。
- active：黄绿边框，外发光弱，背景略亮。
- hover：背景亮度提升。
- focus：键盘轮廓。

交互：

- 点击列表项只改变 `selectedOrder`，不一定跳转详情页。
- 双击或点击右箭头可进入 `/orders/{orderNumber}`。
- 移动端点击列表项可展开详情卡，或直接进入详情页。

### 8. `OrderProgressRail`

横向 5 步进度条。

步骤：

1. 已提交
2. 需求确认中
3. 试跑初版中
4. 待验收
5. 已完成

每步结构：

- 圆形节点，36px。
- 节点内图标：check、search/target、code、hourglass、done。
- 标题。
- 副标题或时间。

状态：

- completed：绿色节点，连接线已完成段黄绿/绿色。
- current：橙色或黄绿色高亮，节点稍大或外发光。
- pending：灰色节点。

实现：

```ts
type ProgressStep = {
  key: "submitted" | "clarifying" | "in_progress" | "review" | "completed";
  label: string;
  hint: string;
  icon: string;
};
```

移动端：

- 改为竖向，节点左侧，文字右侧。

### 15. 空状态和加载状态

无订单：

- 保留工作台框架，但左侧显示“还没有订单”，右侧显示“先写一张小纸条，酷里会帮你判断”。
- CTA：写小纸条、看看热门需求。

加载中：

- 统计卡和列表使用 skeleton，不要整页空白。

错误：

- 显示错误面板和“重新加载”按钮。

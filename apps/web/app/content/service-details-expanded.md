## 1. 文档处理

### 页面标题
文档处理，把乱掉的材料重新收拾成能交的版本

### 页面摘要
PPT 制作、Word 排版、论文格式规范、图片 / PDF 转 Word、扫描件 OCR 和文档重写，都可以先发来

### 介绍
文档最费劲的地方，常常不是写，而是卡在格式、分页、目录、页码、图表、公式、引用和扫描件这些细碎环节酷里会先判断它属于排版、转换、修复、重做还是润色，再选最省事的路径，把它整理成能交的版本

### 我们可以处理什么
- PPT 制作与优化：根据论文、提纲、报告或资料包做演示稿，也可以把现有 PPT 重排、润色成更像样的版本
- Word 排版与格式调整：标题层级、页边距、行距、页眉页脚、页码、目录和参考文献都能统一，复制粘贴留下的格式灾难也能收拾
- 论文与学术格式规范：按学校或期刊要求调整论文结构、图表编号、脚注尾注、附录和参考文献格式
- 图片 / 扫描件 / PDF 转 Word：把截图、照片、扫描件或 PDF 尽量转成可编辑内容，表格、段落和版式结构都会优先保留
- 内容整理与文档重写：把聊天记录、资料包、录音转写稿整理成正式文档，也能润色语气、统一术语和补齐逻辑链
- 表格、图表与数据文档：Excel 清洗、图表制作、数据结果整理成 Word 或 PPT，先把数据讲明白再放进文档里

### 交付思路
- 先看材料，再定格式；先做能交的版本，再做更好看的版本
- 不用先判断是排版、转换、OCR、重写还是润色，把文件和目标效果发来就行
- 复杂源文件会先说明难点，尽量先给你一个可继续编辑的版本

### 处理路径
1. 发材料
2. 判断路径
3. 正式处理
4. 交付微调

### 常见问题
- PDF 能直接转成可编辑 Word 吗？可以试，效果取决于原文件清晰度、排版复杂度和表格比例
- 论文格式能按学校模板改吗？可以，标题层级、目录、页码、图表编号、参考文献和附录格式都能一起处理
- 图片、截图或扫描件也能做吗？可以，通常会先做 OCR，再根据目标格式重新整理排版

### 结束语
把文件发来，酷里先帮你拆问题

## 2. AI 工具与海外服务配置

### 页面标题
把 ChatGPT、Gemini、Claude、Grok 和整套工具链配到能用

### 页面摘要
ChatGPT、Gemini、Claude、Grok、Telegram，以及 Claude Code、Codex、Cursor、Antigravity、API 和中转站配置，都可以先来问

### 介绍
AI 工具本身不难，难的是前面那一长串：账号注册、验证、支付、地区限制、订阅升级、API Key、环境变量、客户端安装、模型选择和中转接入酷里会先帮你解释这些工具分别是什么、强在哪、适合做什么，再按你的用途、设备和预算，协助把能用的那套环境搭起来

### 工具图谱
- ChatGPT / OpenAI：通用 AI 助手，适合写作、翻译、学习、代码和日常办公，也可以协助账号注册、订阅升级和 API 相关配置
- Gemini / Google：Google 的 AI 体系，适合长文阅读、资料处理和 Google 生态联动，也可以协助账号、订阅与使用路径配置
- Claude / Anthropic：长上下文、写作和编程都很强，也能协助 Claude Pro、Team、API 和 Claude Code 配置
- Grok / xAI：更偏实时信息、社交内容和通用问答场景，也可以一起看账号、订阅和使用问题
- Telegram：海外常用通讯工具，适合账号注册、Bot、频道通知、群组协作和自动化提醒
- Claude Code：命令行里的 AI 编程助手，适合在真实代码仓库里读文件、改代码、跑测试和接着做迭代
- Cursor：AI 代码编辑器，适合在项目里快速理解结构、生成组件、定位问题和推进开发
- Codex：面向代码任务的 AI 协作环境，适合写代码、改 bug、补测试和整理仓库
- Antigravity：更偏 Agent / 协作式开发的工具形态，适合把 AI 放进更完整的工作流里
- API Key / 中转站 / SDK：各类模型 API、Key、代理、中转站和 SDK 接入都能一起看，尽量配到能跑

### 交付思路
- 先认识工具，再决定怎么配
- 先讲清楚它是什么、强在哪、适合什么场景，再判断是账号、订阅、API、客户端还是中转配置
- 最终目标不是“有账号”而是“能在你的日常使用里跑起来”

### 处理路径
1. 先讲清楚
2. 再分类处理
3. 落到环境里
4. 留一份说明

### 常见问题
- 账号、订阅、API 和客户端可以一起看吗？可以，很多时候它们本来就是一套问题
- Claude Code、Cursor、Codex、Antigravity 怎么选？可以先按你的目标来分，再选最合适的工具
- Telegram、Google 账号也能一起处理吗？可以，相关账号注册、验证、登录和基础配置都能一起看

### 结束语
把你想用的 AI 工具发来，酷里帮你配到能用

## 3. 小工具开发与全栈代做

### 页面标题
把想法做成能跑的网页、小程序、脚本或软件

### 页面摘要
网站、小程序、爬虫、数据看板、数据库、AI Agent、自动化工具，从 demo 到成品都可以做

### 介绍
很多想法其实不用先组完整团队，也不用先写成厚厚的需求文档你可能只是想要一个页面、一个小程序、一个自动抓数据的脚本、一个内部管理后台、一个 AI 助手，或者一个能拿去演示的 demo酷里可以把这些想法拆开、做出来、接起来，再继续迭代

### 能做的类型
- 网站与网页应用：企业官网、个人主页、产品页、后台系统、数据看板、表单系统、文档站都可以做
- 小程序与轻应用：微信小程序、H5 小应用、活动报名、预约系统、查询工具和轻量后台都能做
- 爬虫与数据采集：公开数据抓取、清洗、去重、导出、定时采集和结果入库都可以配好
- 自动化脚本：批量处理文件、图片、表格、报告、通知和重复任务都可以自动化
- AI Agent 与智能助手：做问答助手、资料库助手、客服助手或者带工具调用的 Agent 都可以
- 软件与内部工具：桌面工具、命令行工具、浏览器插件或面向内部使用的小软件都能做
- 数据库与后端系统：表结构、权限、API、任务队列、上传下载和看板逻辑都能一起配
- 设计系统与原型：页面结构、组件、视觉风格和可点击原型都可以先搭出来

### 交付思路
- 先做能跑的版本，再把想要的细节一点点补上
- 你负责讲场景和目标，我们负责把需求拆成页面、接口、数据和交付
- 目标不是“先把东西做大”，而是“先把核心流程跑通”

### 开发路径
1. 先定目标
2. 拆成模块
3. 先做 demo
4. 继续迭代

### 常见问题
- 可以先做 demo 吗？可以，很多项目先做一个能跑的版本，再慢慢完善成品
- 能接手半成品或别人写了一半的项目吗？可以，先看代码结构、依赖和报错，再判断接手方式
- 前端、后端、数据库和部署都能一起做吗？可以，默认就是按完整链路来考虑

### 结束语
把想法发来，酷里帮你拆成能做的产品

## 4. 部署配置与服务器运维

### 页面标题
把服务器、域名、数据库和上线环境一次理顺

### 页面摘要
服务器部署、网站上线、VPN、堡垒机、母子网、云算力、域名申请和 DNS，都可以先问

### 介绍
项目做出来以后，真正让人头疼的往往是上线和配置：服务器怎么买、域名怎么注册、DNS 怎么配、HTTPS 怎么开、数据库怎么连、端口为什么不通、反向代理怎么写、后台服务怎么守护、VPN 怎么部署、远程连接怎么更安全酷里可以把这些基础设施问题拆开处理，从可用性、稳定性和安全边界一起看

### 能做的类型
- 网站与应用部署：前端、后端、API、静态站和全栈项目都可以按生产方式上线，环境变量、构建和进程守护也能一起处理
- 服务器购买与管理：云服务器选型、初始化、SSH、权限、防火墙、更新和基础安全加固都能看
- 域名申请与 DNS：域名注册、解析、子域名、SSL 证书和绑定配置可以一起处理
- VPN 与远程访问：合规场景下的远程连接、设备互联和访问控制方案可以协助配置
- 母子网 / 内网 / 堡垒机：VPC、子网、路由、安全组、跳板机和内网访问方案可以一起看
- 数据库与存储部署：PostgreSQL、MySQL、Redis、对象存储、备份和恢复都能一起配
- 云算力与 AI 环境：GPU 云服务器、Python、CUDA、PyTorch、Jupyter 和远程开发环境都可以配
- 反向代理 / 网关 / 中转：Nginx、Caddy、HTTPS、负载均衡、路径转发和 CORS 问题都能排查
- 运维排查与安全加固：启动失败、端口冲突、日志定位、备份恢复和基础安全加固都可以处理

### 交付思路
- 能上线只是开始，能稳定跑、能查错、能维护，才算真的配好
- 服务器、域名、证书、数据库、网络、安全、日志和备份会一起看，不只帮你敲几条命令
- 需要先把权限和边界讲清楚，再往下配

### 故障路径
1. 说明现状
2. 选方案
3. 上线排查
4. 留文档

### 常见问题
- 能不能只帮我排查服务器问题？可以，服务起不来、端口不通、数据库连不上、证书报错这些都能先看
- 域名和 HTTPS 也可以一起配吗？可以，域名注册、DNS、证书和反向代理通常本来就要一起处理
- VPN、堡垒机和内网互联有什么区别？它们解决的是不同层次的访问问题，我们会先按你的场景选合适的方案

### 结束语
把服务器、域名或报错截图发来，酷里帮你部署排查
